# Windows 0.13 / WASM 0.15 — уточнение качества

26.10.2026. Основа сравнения — 63f7d6a, Windows 0.12 / WASM 0.14. Изменения не используют палитру или геометрию экспорта VM при трассировке.

## Реализация предложенных направлений

1. **Число цветов адаптивно.** Для лимитов 2–24 сначала ищутся реальные внутренние цвета. Если они объясняют не менее 96% выборки, возвращается меньше цветов, чем заданный максимум. Для небольших сглаженных рисунков допускается 75% прямого покрытия при объяснении 99.5% пикселей смесями этих цветов с RGB-ошибкой до 8. Фото, не прошедшие проверку, получают взвешенную гистограмму: веса count^0.75, бюджет около 60000 образцов, пять инициализаций. Это уменьшает господство самых больших цветовых областей. Явный пользовательский RGB-список не меняется.
2. **Совместное уточнение цветов и назначения.** В предложении палитры взвешенный Lloyd чередует назначение образцов кластерам и обновление центров до 35 итераций, затем берутся медианы. Это совместная кластеризация на стадии предложения; она не является совместной глобальной оптимизацией пространственного графа и палитры после трассировки. Изменять вручную выбранные цвета по исходнику нельзя.
3. **Субпиксельная граница по исходнику.** После сглаживания общего графа двухцветные узлы смещаются вдоль нормали на один из вариантов ±0.125 / ±0.25 px. Функция ошибки сравнивает долю смеси двух цветов с наблюдением билинейно восстановленного premultiplied RGBA. Регуляризация ограничивает движение. Развилки, край изображения, малые циклы и слабоконтрастные пары закреплены.
4. **Единая геометрия соседей.** Общий граф уже был в фото-пути; уточнение применяется к нему один раз. Оба соседних цвета получают одинаковую вершину и радиус. Порядок обхода цепочек Python согласован с Rust. Графический Potrace-путь сохраняет независимый аудит/разбиение геометрии и RGB-группы PDF.
5. **Уточнение кривых по покрытию.** Для каждой подходящей общей вершины проверяются радиусы 0.5 / 1 / 1.5 / 2 px. Квадратичная дуга, точно представленная кубической Безье, оценивается в трёх точках по локальной функции покрытия. Выбирается улучшение с регуляризацией. Это ограниченный локальный inverse-raster fit, а не глобальный оптимизатор всех управляющих точек по полному повторно отрисованному изображению. Полный целочисленный аудит пересечений остаётся обязательным; при отказе действует прежний безопасный путь.
6. **Очистка с защитой деталей.** Для ограниченной палитры/графики маленькая область объединяется только с соседним наиболее частым цветом при RGB-дистанции до 35; вытянутые области шириной до двух пикселей и длиной от трёх защищены. Контрастные островки/отверстия сохраняются. В свободном фото-пути прежняя очистка оставлена: её замена в промежуточном опыте увеличила число областей и не дала достаточного основания включать её там.

Python и Rust содержат соответствующие реализации. Windows OpenCL FP64 вычисляет локальную ошибку покрытия; фильтры, назначение/пространственные проходы, сглаживание, RDP и арифметика кривых используют существующие GPU-пути. Топология, кластеризация, решения о слиянии и аудит — CPU. В браузере новый локальный fit выполняет Rust, WebGPU выполняет фильтры/сегментацию и подходящие крупные общие контуры. Перенос новой функции ошибки на WebGPU с тем же качеством здесь не заявляется. Отсутствие GPU/FP64 даёт явный CPU fallback.

## Испытания

Сохранённый внешний набор: 12 изображений, четыре профиля, 48 эталонов настоящей VM 1.15. Новые имена прогонов desktop-quality-final / wasm-quality-final; прежние результаты не перезаписаны. Windows использует GPU, Node/WASM — CPU; эквивалентность ускорения проверяется отдельно. Для ограниченной палитры сравнивается одинаковый UI-лимит, а не одинаковые сгенерированные RGB: именно подбор RGB изменяется. Явный `--proposal-comparison` допускает это отличие и вычислительный backend, сохраняет обе конфигурации и не ослабляет обычный режим проверки baseline.

На соответствующих типах входа Windows:

| Режим | MAE до | MAE после | Снижение |
|---|---:|---:|---:|
| Фото, среднее, 9 слотов | 10.084 | 8.015 | 20.5% |
| Фото, высокое, свободно | 3.834 | 3.760 | 2.0% |
| Фото, среднее, свободно | 4.532 | 4.457 | 1.7% |
| Рисунки, среднее, 9 слотов | 0.832 | 0.716 | 13.9% |
| Схемы, среднее, 9 слотов | 0.226 | 0.226 | 0% |

Это не равномерное улучшение: Chelsea с ограниченной палитрой ухудшается (в соответствующем фото-профиле и стрессовом графическом). Пороговые регрессии сохранены в отчётах. Набор участвовал в разработке — независимое обобщение не доказано. Все 48 межверсионных проверок прошли допуски (включая прежний сбой на QR). Ошибка восьми рисунков относительно исходного SVG при ×4 снизилась с 0.820 до 0.665; у VM она составляет около 0.193. Межверсионные числа и все 48 случаев см. [QUALITY_015_RESULTS.json](QUALITY_015_RESULTS.json). Локальная HTML-сводка — build/quality-public-v2/reports/quality-release/index.html.

GTX 1080, среднее фото / 9 слотов, прогрев и три чередующихся замера полной трассировки нового алгоритма: astronaut CPU 6.13 s / GPU 4.18 s (1.47×), coffee 6.62 / 4.98 s (1.33×). SVG CPU/GPU побайтно одинаковы. Это сравнение backend текущей версии, не старой и новой версий и не скорости VM.

Проверки: восемь новых автоматических/ручных, непрозрачных/прозрачных примеров в tests/quality_refinement.py; четыре реальных включения OpenCL функции покрытия. Проверены малые контрастные области, тонкие линии, дырки, адаптивное число цветов, CPU/GPU и Python/Rust. Дополнительно photo_regions, curves_parity (18 случаев), photo_detail, pdf_color_groups, palette_ui и старые 168 точных CPU/GPU контуров. Браузер: 12 GPU-фильтров, 12 mode-фильтров, 36 пространственных назначений, 24 контура и два полных Worker; размеры UI 390/640/820/1280. Собранный EXE проверен отдельной трассировкой с аудитом и действующим OpenCL fit.

## Воспроизведение

```powershell
python tests/quality_refinement.py
python quality/bench.py --corpus build/quality-public-v2 compare --run desktop-quality-final --baseline desktop-public-v2 --name new-desktop-report --proposal-comparison --require-complete
```

При обнаруженных регрессиях compare завершает работу с ненулевым кодом и сохраняет отчёт. Этот preview публикуется с явным описанием ухудшений; все gates качества не объявляются зелёными. Полная идентичность VM не достигнута.

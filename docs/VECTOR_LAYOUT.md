# Windows 0.8 preview: цветовые группы и геометрия без наложений

Результат трассировки проходит обязательное устранение наложений перед показом
и экспортом. Для каждого RGB в SVG создаётся одна настоящая группа `<g>`
с `id="color-RRGGBB"`. Несвязанные компоненты остаются отдельными путями внутри
своей группы; отверстия сохраняются в составном пути. Это избегает ограничений
Qt на слишком большой путь одного цвета. SVG не использует скрывающие маски,
clipPath, stroke или растровые изображения для имитации удаления наложений.

Закрытая верхними объектами часть нижнего объекта удаляется из его геометрии.
Это относится к разным и одинаковым цветам, включая прежнюю общую подложку
прозрачной иллюстрации. Предпросмотр и SVG/EPS/PDF используют один результат.
SVG сохраняет редактируемые группы; EPS хранит последовательные пути одного
цвета, но не обещает группировку объектов в стороннем редакторе.

## Точность и проверка

Булевы операции Skia PathOps сохраняют кривые там, где результат проходит
независимую проверку пересечений. Работа разделена на участки 128×128 с общими
границами. Из-за численных сбоев операций над сложными кривыми некоторые участки
пересчитываются Clipper на сетке 0.0000001 рабочего пикселя. Перед этим Qt делит
кривые на линейные участки при масштабе 64×. Такой резервный результат может
содержать больше узлов и линейных сегментов. Количество резервных участков
показывается в `partition_polygon_tiles`.

**Допуск проверки площади пересечения — 0.0001 рабочего пикселя² на пару путей.**
Это конечная численная точность, а не обещание математического нуля при
произвольном увеличении. Каждый участок проверяется отдельным целочисленным
алгоритмом, включая резервный результат. При превышении допуска задание
заканчивается ошибкой, вместо сохранения заведомо перекрывающихся объектов.
Проверка учитывает также пути одного цвета, отверстия и стыки участков.

`tests/vector_partition.py` проверяет реальные векторные пересечения, сохранение
объединения областей, отверстия/островки, 16000 случайных точек владения цветом,
стыки 128×128, принудительный резервный алгоритм и EPS сгруппированного SVG.
Визуальные метрики не заменяют эти проверки. Из-за устранения перекрытий
антиалиасинг Qt может показывать тонкие линии на общих границах; добавление
перекрывающего stroke для их маскировки не применяется.

## Производительность и GPU

Назначение фиксированной палитры, AA-коррекция и включённая пространственная
сегментация фото работают на OpenCL GPU при подходящих настройках/размере;
контекст сохраняется в рабочем процессе, метки пространственных проходов
остаются в VRAM до итоговой выгрузки. CPU fallback сохранён. Это реальное
исполнение GPU, а не только запрошенное значение настройки.

Новый этап геометрии работает на CPU. Для крупных работ участки обрабатываются
четырьмя отдельными процессами. Простое добавление Python-потоков не ускоряло бы
Skia bindings, удерживающие GIL. Геометрические процессы не создают GPU-контексты.
Устранение наложений добавляет время; нельзя переносить ускорение сегментации на
весь этот этап. Фото без ограничения цветов по-прежнему обрабатывается CPU.
WASM не менялся.

Статистика содержит `compute`, `device`, `geometry_compute`, `geometry_workers`,
`partition_seconds`, `partition_tiles`, `partition_polygon_tiles`,
`geometry_verified` и `overlap_tolerance_px2`.

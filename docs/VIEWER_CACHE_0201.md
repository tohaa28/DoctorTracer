# DoctorTracer — проверка конкурентной загрузки SVG для предпросмотра

**Дата:** 30.10.2026. **Основа:** `spatial-photo-preview` / `868ce84e0ab5ed3d0f5ee38ef372269ccbcfef2f` (viewer 0.20.1).

## Причина и решение

После исправления прокрутки предпросмотр в браузере может запрашиваться несколько раз до завершения асинхронного `Image.decode()`. Прежний `web/preview.mjs` начинал новый decode на каждый такой вызов, даже при одинаковом SVG. При быстрой смене разных SVG старый decode мог поздно перезаписать единственный кэш. Это не подтверждённая потеря геометрии экспорта, а воспроизводимая проблема конкурентной загрузки в модуле просмотра.

Теперь ожидающие декодирования SVG хранятся в `Map`, и одинаковые параллельные запросы используют одну операцию `Image.decode()`. Каждый вызов рисует именно свой SVG, а кэш последнего изображения обновляется только для последнего запрошенного SVG. Blob URL освобождается в `finally`, включая ошибку; неудачное декодирование можно повторить. Экспорт, геометрия, палитра, Rust/WASM и формат PDF не менялись.

## Испытания

`node tests/preview_cache.mjs` — PASS: два параллельных одинаковых SVG (один decode); A/B с завершением B раньше A; повтор B без декодирования; отказ декодирования, повтор и освобождение Blob URL. `node --check web/preview.mjs` и `node --check tests/preview_cache.mjs` — PASS. Это тест асинхронной логики с подменённым DOM, **не** запуск в настоящем браузере и **не** проверка CorelDRAW/Windows. Реальная визуальная проверка, GPU и Windows-сборка в этой среде не выполнялись.

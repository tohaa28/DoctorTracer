# GPU-контуры: Windows 0.12 / WASM 0.14

26.10.2026. Базовая версия: 02373c0 (Windows 0.11.1 / WASM 0.13.1).

## Перенесено на GPU

Windows/OpenCL FP64: диффузия общих узлов, упрощение цепочек Douglas–Peucker, контрольные точки кубических кривых. Не используется fast-math, свёртка FMA отключена. Узлы общие для соседних цветов; закрепление развилок, границ изображения и малых циклов сохранено. Нет FP64, ошибка устройства или цепочка длиннее 65536 точек — штатный CPU-путь с явной причиной в метриках. Копирование предварительного сегментированного изображения в браузере заменено передачей буфера.

WASM/WebGPU: классификация рёбер, закрепление узлов и сглаживание координат. Координаты хранятся в целых с масштабом 4^passes: результат совпадает с CPU double, без float32-сдвигов. Ограничение переполнения и размера GPU-буфера проверяется до запуска. Rust получает готовые координаты и не повторяет сглаживание. При отказе WebGPU продолжает ту же отложенную операцию на CPU.

Связность цепочек, упорядоченное объединение областей, финальная сборка SVG, Potrace для графики и независимый целочисленный аудит пересечений остаются на CPU. Это фактическая гибридная реализация; перевод всей геометрии на GPU не заявляется.

## Сравнительные замеры Windows

GTX 1080, исходные размеры 800×954 и 568×960, фото / среднее качество / 9 общих слотов либо свободная палитра. На прозрачном изображении 9 слотов = 8 RGB + прозрачность. До и после включены одинаковые существующие GPU-фильтр и сегментация. Прогрев обеих реализаций и кэша палитры; затем по три чередующихся замера без cProfile. Таблица — медианы полной трассировки с аудитом, секунды.

| Лев | Свободная | 11.41 | 10.46 | 1.09× |

Каждый SVG во всех замерах побайтно совпадает с базовой версией. Максимальная площадь пересечений — 0 px² во всех четырёх случаях, порог 0.0001 px². Исходные фото и SVG хранятся только в build/gpu-contours. cProfile использовался для поиска узких мест, его завышенные времена не включены в эту таблицу.

## Отрицательный результат и выбор пути WASM

На ограниченной палитре принудительный WebGPU shared finish оказался на 1.6–4.9% медленнее Rust из-за передачи плотной сетки, несмотря на точное совпадение SVG. Поэтому этот путь по умолчанию остаётся Rust. Для крупного льва со свободной палитрой стадия shared finish: 692.5 → 643.1 мс (1.08×); фигурка: 323.2 → 320.5 мс, недостаточный выигрыш. Автоматический GPU-путь ограничен крупными фото от 700000 пикселей со свободной палитрой и средним/низким качеством (8/10 проходов). Это измерения стадии, не время всей браузерной трассировки. Перенос, компиляция и производительность зависят от устройства; универсального ускорения не заявляется. Начальные неудачные замеры сохранены локально.

## Проверки и повторение

- tests/gpu_contours.py: 168 побайтных сравнений SVG, 1/2/4/5/8/10 проходов, 7 допусков, дубли RGB, прозрачность, тонкие части, диагонали, отверстия; искусственный отказ GPU и CPU fallback.
- tests/gpu-contours.html: 24 точных CPU/WebGPU SVG, отложенное продолжение на CPU; 2 полных Web Worker с точным SVG и реально задействованным WebGPU; тест автоматического выбора ускоренного пути.
- tests/gpu_contours.mjs: 6 отложенных CPU-продолжений, проверка неверной длины входных координат.
- tests/gpu-contours-perf.html: локальные полноразмерные RGBA из build/gpu-contours/browser-cases.json, до/после и независимый аудит.
- scripts/bench_gpu_contours.py --image ... --image ... --repeats 3 --browser-cases: извлекает baseline из Git, прогревает обе версии, чередует замеры, требует точный SVG.
- Существующие tests/rust_wasm.mjs, tests/photo_detail.py, tests/palette_ui.py/.mjs, tests/pdf_color_groups.py и tests/browser.html проверяют регрессии.

Полные агрегированные числа: [GPU_CONTOURS_014_RESULTS.json](GPU_CONTOURS_014_RESULTS.json). Эти тесты доказывают сохранение результата текущего алгоритма на проверенных входах; новая близость к Vector Magic здесь не заявляется.
